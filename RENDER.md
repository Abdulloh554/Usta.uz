# Deploying to Render

The API validates its whole environment at boot (`src/config/env.ts`) and throws
instead of starting half-configured. That is why a missing variable shows up as
a failed deploy with

```
Error: Invalid environment configuration:
  - MONGO_URI: Required
  - REDIS_URL: Required
```

rather than as a broken endpoint later. Four variables have no default and must
be set; everything else falls back to a working value.

| Variable | Why it has no default |
| --- | --- |
| `MONGO_URI` | The Atlas connection string, credentials included. |
| `REDIS_URL` | SMS codes, refresh-token allow list, matching queue, socket fan-out. |
| `JWT_ACCESS_SECRET` | At least 32 characters. |
| `JWT_REFRESH_SECRET` | At least 32 characters, different from the access secret. |

## Option A — blueprint (recommended)

`render.yaml` declares the web service and a free Key Value instance together,
so `REDIS_URL` is wired automatically and both JWT secrets are generated by
Render. In the dashboard: **New → Blueprint**, pick this repository, and fill in
`MONGO_URI` when prompted. Delete the old manually-created service afterwards so
two services are not pointed at the same database.

## Option B — keep the existing service

1. **Create the Key Value instance.** *New → Key Value*, free plan, same region
   as the web service, `maxmemory-policy` set to `noeviction` — BullMQ keeps job
   state there, and evicting a key silently drops a queued match. Copy its
   **Internal Connection String**.
2. **Set the environment variables** on the web service (*Environment* tab):

   ```
   NODE_ENV=production
   API_PREFIX=/api/v1
   LOG_LEVEL=info
   MONGO_URI=<Atlas connection string>
   REDIS_URL=<internal connection string from step 1>
   JWT_ACCESS_SECRET=<32+ characters>
   JWT_REFRESH_SECRET=<32+ characters, different>
   SMS_PROVIDER=console
   ORDER_ACCEPT_FEE=4999
   ```

   Do not set `PORT`; Render injects it and the app already reads it.
3. **Fix the build command.** Render sets `NODE_ENV=production`, and TypeScript
   lives in `devDependencies`, so the default install skips it and `tsc` is not
   found. Use:

   ```
   Build Command:  npm ci --include=dev && npm run build
   Start Command:  npm start
   ```
4. **Set the health check path** to `/health`.

## MongoDB Atlas network access

Free Render services connect from a changing set of outbound addresses, so a
narrow Atlas allow list rejects them and the deploy fails on the *next* step
with `MongooseServerSelectionError`. In Atlas, under *Network Access*, allow
`0.0.0.0/0` and rely on the connection-string credentials, or move to a paid
Render plan and allow its static outbound IPs instead.

## Verifying

`GET /health` reports both backing services, so it distinguishes "the process is
up" from "the process can actually serve traffic":

```json
{ "success": true, "data": { "status": "ok", "mongo": "up", "redis": "up" } }
```

If `redis` reads anything other than `up`, the instance is unreachable — check
that it is in the same region and that the **internal** connection string was
used, not the external one.

## SMS

`SMS_PROVIDER=console` only writes the verification code to the log, which is
what you want until the Eskiz account is live. Switching to `eskiz` without
`ESKIZ_EMAIL` and `ESKIZ_PASSWORD` makes every login fail, so set those two in
the same change.
